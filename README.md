# ReceiptRelay — AI Financial Operations Agent\n\nThis upgrade preserves the original client document checklist and adds a PayPal Sandbox invoice workspace, transaction retrieval, Gemini analysis, reconciliation recommendations, human approval records and verified webhook handling.\n\n## Features\n- Existing: client CRUD/search, missing/received document checklist, friendly/direct email or WhatsApp drafts, copy, CSV export, browser-local persistence.\n- New: invoice overview, PayPal Sandbox invoice create/list/send, PayPal Transaction Search, Gemini AI recommendations with clearly labelled deterministic fallback, editable reminder drafts, approval/audit records, webhook signature verification and event deduplication.\n- Only verified PayPal invoice-paid webhook events update payment status.\n\n## Requirements\nNode.js 20+, npm, PayPal Developer Sandbox REST app, and optionally a Gemini API key.\n\n## Run locally\n```bash\nnpm install\ncp .env.example .env\ncp server/.env.example server/.env\n````\nSet root `VITE_API_URL=http://localhost:5000`. Add PayPal and Gemini credentials only to `server/.env`. Do not commit `.env`.\n```bash\nnpm run dev\n```\nFrontend http://localhost:5173; backend health http://localhost:5000/api/health.\n\nProduction-style single process:\n```bash\nnpm run build\nnpm start\n```\n\n## PayPal Sandbox\n1. Create a REST app at https://developer.paypal.com/dashboard/ under Sandbox.\n2. Set `PAYPAL_CLIENT_ID` and `PAYPAL_CLIENT_SECRET` in `server/.env`. Keep `PAYPAL_BASE_URL=https://api-m.sandbox.paypal.com`.\n3. Restart backend. Open Finance Agent → Integration setup. Create invoice with a Sandbox buyer email; use Send to send through Sandbox. Without credentials, invoices are local demo records and cannot be sent.\n\n### Webhooks\nDeploy with HTTPS. Register `https://YOUR_HOST/api/webhooks/paypal` in the Sandbox app, subscribe to `INVOICING.INVOICE.CREATED`, `SENT`, `UPDATED`, `PAID`, `REFUNDED`, and set `PAYPAL_WEBHOOK_ID`. Test webhook delivery in PayPal Developer Dashboard. Signature verification is mandatory.\n\n## Gemini\nCreate a key at https://aistudio.google.com/app/apikey and set `GEMINI_API_KEY` in `server/.env`. Optional model setting: `GEMINI_MODEL=gemini-2.5-flash`. If no key is configured, the deterministic rules engine runs and is explicitly labelled as such.\n\n## API routes\n| Method | Route | Purpose |\n|---|---|---|\n| GET | `/api/health` | Integration status |\n| GET | `/api/invoices` | List local and PayPal invoices |\n| POST | `/api/invoices` | Create invoice |\n| POST | `/api/invoices/:id/send` | Send PayPal Sandbox invoice |\n| POST | `/api/paypal/transactions` | Search transaction records |\n| POST | `/api/agent/analyze` | AI/rules analysis |\n| POST | `/api/agent/approve` | Record approval |\n| GET | `/api/audit` | Audit/approval history |\n| POST | `/api/webhooks/paypal` | Verify and process webhooks |\n\n## Safety and limitations\nSandbox-only; no live switch. No transfers/payouts/refunds. No automated email/WhatsApp. Approval records are audit notes only. AI never changes payment status. Amount matches are candidates only. No authentication, tenant isolation, production database or production privacy controls. Use synthetic data only. JSON persistence is demo-only. Read `docs/SECURITY_AND_COMPLIANCE.md`.\n\n## Hackathon submission\nOfficial rules: https://paypalaihackathon.devpost.com/rules.
