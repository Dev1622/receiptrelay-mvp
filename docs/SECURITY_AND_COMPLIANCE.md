# Security, PayPal integration and hackathon compliance\n\nThis is a hackathon prototype, not a certified accounting or payment product. Review the current PayPal Developer Agreement, API terms, privacy requirements and hackathon rules before use.\n\n## PayPal safeguards implemented\n- PayPal Sandbox base URL is the default; no live-mode toggle is provided.\n- Client ID and Secret are server-only environment variables. Never put them in `VITE_*` variables or commit `.env`.\n- OAuth 2.0 client-credentials flow is server-side with token caching.\n- Invoice create/list/send use PayPal REST Invoicing endpoints.\n- Transaction Search retrieves transaction evidence.\n- Webhook signatures are verified through PayPal's verification API using the configured webhook ID.\n- Webhook event IDs are deduplicated. Only verified `INVOICING.INVOICE.PAID` events update payment status.\n- Amount-only matching is a candidate, never proof of payment.\n- Sending a PayPal invoice requires explicit UI confirmation.\n- No transfers, payouts, refunds, or other money movement are initiated.\n- No emails or WhatsApp messages are sent; drafts require manual sending outside this app.\n\n## Webhook deployment\nDeploy behind HTTPS. Register `https://YOUR_HOST/api/webhooks/paypal` in the PayPal Sandbox app. Subscribe to invoice events such as CREATED, SENT, UPDATED, PAID and REFUNDED. Set `PAYPAL_WEBHOOK_ID`. For production add a durable queue, database uniqueness constraint, replay monitoring, out-of-order event strategy, alerting and dead-letter handling.\n\n## Prototype data limits\nNo authentication, tenant isolation, role-based access, encryption-at-rest policy, retention controls or production database is included. JSON storage is for local demonstration only. Use synthetic sandbox data; do not enter real customer data. Gemini receives the records included in the analysis request. Before production add privacy policy, terms, data export/deletion, support contact, security review, and tenant-aware database access controls. AI output is untrusted and cannot change payment status.\n\n## Hackathon checklist\nCheck the official rules at https://paypalaihackathon.devpost.com/rules. The current rules require: Devpost registration and eligibility; an application integrating PayPal Developer Platform Sandbox and an AI tool; significant updates to any pre-existing project during the submission period; public source repository with an open-source license; functional demo or reproducible setup instructions; and a public YouTube demonstration under three minutes. Explain the actual changes made during the submission period. This checklist is not legal advice and does not imply PayPal approval or certification.\n\nOfficial references:\n- https://paypalaihackathon.devpost.com/rules\n- https://developer.paypal.com/api/rest/\n- https://developer.paypal.com/docs/api/invoicing/v2/\n- https://developer.paypal.com/api/rest/webhooks/\n- https://developer.paypal.com/docs/api/transaction-search/v1/\n
